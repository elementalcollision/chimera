## Findings

1. **qwen3.7-max is the value leader.** It tied kimi for a perfect 104/104 AND
   was the cheapest model (~29% below kimi, ~52% below deepseek), winning 3 of 4
   probes on the cost tiebreak. A kimi-vs-deepseek-only A/B would never have
   surfaced this — the full field was worth running.

2. **qwen and kimi are co-quality-leaders (both perfect).** At the top this is
   NOT a noise artifact — you can't beat 104/104 across all four difficulty
   tiers. So the quality tie between them is real; cost is the deciding signal,
   and it favours qwen.

3. **The grader is discriminating, so the perfect scores are credible.** It gave
   deepseek 91% and glm 95% (catching deepseek's slugify 8/16 and intervals
   16/17, and glm's duration 13/18) — it is not a pass-everything oracle.

4. **deepseek-v4-pro is the laggard** (91%, priciest) — consistent with the
   earlier battery where it wobbled on the interpretation-heavy probes.

5. **The current promoted lead (kimi) is co-best on quality but not the value
   pick.** qwen dominates it weakly: equal quality, lower cost.

## Caveats

- **Single trial per cell.** Quality ranks are noisy in general — but the two
  leaders both maxed out (perfect on every probe), so their quality parity is
  solid; only a regression-under-repetition could separate them, and the cost
  gap is the robust signal regardless.
- **Probes are small/synthetic.** They exercise correctness + validation on
  bounded tasks, not large multi-file changes. Real CRAWL work differs; the
  outcome ledger remains the in-production monitor.

## Recommendation (operator-gated)

The arena says **qwen3.7-max ≥ kimi on quality and cheaper** → qwen is the
strongest value lead for the code tier. Two defensible paths:

- **(a) Confirm, then flip:** a short multi-trial run on the two perfect models
  (`AB_TRIALS=3`, qwen vs kimi) to verify qwen's parity holds under repetition
  before a second routing change — avoids ping-ponging the lead on n=1 data.
  *Recommended* (we just promoted kimi).
- **(b) Flip now:** point the code tier's lead at qwen — non-inferior on quality,
  cheaper, low downside (draft-PR-only, fallback ladder, ledger monitors). Same
  risk profile as the kimi promotion, just better-supported.

Either way the ladder ORDER question is open: a reasonable code ladder might be
`qwen3.7-max → kimi-k2.7-code → glm-5.1 → deepseek-v4-pro → opus` (value-first),
vs today's `kimi → deepseek → glm → qwen → opus`.

## Operational

16/16 soaks ran clean (after a restart — see below). All worktrees pruned;
nothing merged. **Sizing lesson:** the first launch used a 16384 output cap "for
fairness," but kimi (reasoning-heavy) burned ~9 min/ACT-call generating into it
on tiny-diff probes → ~9h projected. Restarted at 8192 (sufficient for these
probes, uniform across models) → ~3h. The 16384 *production* default for the
code tier stays — it's for real large-diff CRAWL work, not this micro-benchmark.
