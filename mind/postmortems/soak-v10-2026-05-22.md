full v4.86 → v4.100 chain in place. The first soak to reach phase 2
*fast and clean* (v4.98 runner fix proved itself). Also the first
soak to surface a failure class no prior detector covers: **the
agent edits `chimera/X.py` introducing a syntax error, and every
subsequent runner iteration crashes on import** without any
detection layer noticing.
**Outcome:** v10 spent 13 minutes spinning on `SyntaxError:
invalid syntax` after the agent's `chimera/core/act.py` edit
produced structurally invalid Python. No agent commits landed.
Trust collapsed T5 → T1 on 2× scope_evasion before the syntax
issue silently took over. Operator killed at $0.15 / $10.
**Operator decision:** Stop and write the post-mortem. The new
failure class (`syntax_invalid` / `import_failure`) is a clean
v4.101 chip — a `python3 -m py_compile` check on every agent
write to `*.py` would have caught this in the first round.

## The broken patch

The agent's "Implement the fix" attempt produced this uncommitted change to `chimera/core/act.py:1515-1530`:

```python
            for tu in response.tool_uses:
                args = normalize_tool_input(tu.input)
                batch_args.append(args)
                history.append(ToolCall(name=tu.name, args=args))

            if verdict is LoopVerdict.OK:          ← inserted
                verdict = detect_ping_pong(history) ← inserted
                return ActResult(                   ← opens function call
            verdict = detect_degenerate_loop(history)   ← left over, dedented
            if verdict is LoopVerdict.ABORT:            ← left over
                    task_text=task_text,        ← still inside the dangling ActResult( from line above
                    completed=False,
                    rounds=round_idx + 1,

                    write_targets=write_targets,
                    tool_call_history=history,
```

The agent had the right INTENT (`if OK, also check ping_pong`) but spliced it into the existing return-statement incorrectly. The structural result is two `ActResult(` constructors and a dangling `return` with no closing paren. **Python can't parse this; every subsequent import of `chimera.core.act` raises `SyntaxError`.**

A `python3 -m py_compile chimera/core/act.py` immediately after the write would have exited non-zero with the line number. None of the existing detectors run such a check.

## The new failure class — v4.101

**`syntax_invalid` / `import_failure`** — agent-edited Python that
doesn't parse.

The detector design:

```python
def check_syntax_valid(write_targets: list[str]) -> list[tuple[str, str]]:
    """Returns [(path, error_msg), ...] for any *.py path in write_targets
    that fails python compilation."""
    failures = []
    for path in write_targets:
        if not path.endswith(".py"):
            continue
        if not Path(path).exists():
            continue
        result = subprocess.run(
            ["python3", "-m", "py_compile", path],
            capture_output=True, text=True, timeout=5,
        )
        if result.returncode != 0:
            # Extract "line N" + "SyntaxError: ..." from stderr
            msg = result.stderr.strip().split("\n")[-1]
            failures.append((path, msg))
    return failures
```

Wired into ACT at the same point as `check_fix_without_test`:

```python
if completed:
    syntax_failures = check_syntax_valid(write_targets)
    if syntax_failures:
        completed = False
        finish_reason = "syntax_invalid"
        # field on ActResult for the failures list
```

Trust delta in v4.93 table: **-1 (moderate)**. The agent CAN recover from syntax errors with a hint pointing at the specific line; treating it as severe (scope_evasion-level) would be over-punitive for an "edge case" failure of an otherwise honest fix attempt.

Remediation hint: `"Your write to <path> at line N produced invalid Python: '<msg>'. Read the file context around line N, identify the structural issue, and rewrite the affected block cleanly. Don't analyse — just fix the syntax."`

The v4.101 chip is the natural next layer — and notably, it would have caught v10's failure in the FIRST iteration instead of letting it spin for 13 minutes.

## Why v4.95 didn't auto-promote

v4.95's `chimera trust degrade-check --auto-promote` runs **at cycle
boundaries**. Phase 2 was still inside cycle 131's ACT phase when
trust collapsed T5 → T1 across 2 escalations. degrade-check fired
ONCE at phase 1 start (`baseline=T5 current=T5 drop=0`) and has not
been invoked again because cycle 131 hasn't completed.

This is a **calibration miss in v4.95**, not a bug. The runner hook
runs between ACT phases, but trust can collapse multiple tiers
**within a single ACT phase** (across multiple task escalations
inside cycle 131's ACT block). Either:

- v4.95 hook needs to also run after every escalation (more
  frequent invocation), OR
- v4.93 should cap per-cycle trust decrement (e.g., max -1 per
  cycle from ungrounded_citation; max -2 per cycle from
  scope_evasion).

The v4.101 chip should mention this as a related concern.

## Chips for v4.101+

1. **v4.101 — `syntax_invalid` finish_reason.** Run
   `python3 -m py_compile` on every agent-edited `.py` file in
   `write_targets`. If non-zero exit, downgrade `completed=True →
   False` with `finish_reason="syntax_invalid"` and route v4.84
   hint pointing at the specific line+error. Trust delta -1.
   Wired ACT-side at the same point as `check_fix_without_test`.
   ADR 0105.

2. **v4.102 — v4.95 hook runs after each escalation, not just at
   cycle boundary.** Or: cap per-cycle trust decrement at -2.
   Either prevents the T5 → T1 collapse-in-a-single-cycle that
   v10 exhibited. Companion to v4.101.

3. **v4.103 — pre-commit equivalent for agent commits.** When the
   agent runs `git commit`, run `py_compile` on every staged `.py`
   file as a gate. If invalid, refuse the commit and surface the
   error. The runner already runs commit detection in
   write_targets-finalization; this is a natural augmentation.

4. **v4.104 — runner detects "process keeps crashing" pattern.**
   When `chimera run` exits with non-zero N times in a row with
   the SAME error pattern, abort the phase, snapshot the failing
   state, and surface it for operator review. v10 spun 13 minutes
   on the same SyntaxError without the runner noticing.

## Closing observation

Ten soaks deep, the platform has now exercised the entire stack
from "is the right task being picked?" (v1) up through "is the
agent's self-report internally consistent?" (v9) and now into "is
the agent's WORK actually valid?" (v10). The detectable surface
grows one layer per soak, and the soak series has shifted from
"validate that the agent can ship at all" (v1-v6) to "validate
that the agent ships honest, complete, and CORRECT work" (v7+).

The trajectory remains real. v6 was the first chimera/ function
definition. v9 was the first chimera/ wiring commit. v10 was the
first chimera/ edit-that-tried-but-broke. The next soak — once
v4.101 ships — should answer: can the agent self-correct a
syntax error from a structured hint pointing at the exact line?
If yes, the agent's now navigating the full edit→compile→fix
loop autonomously. That's a significant capability gradient to
have crossed in 10 soaks of platform work.
