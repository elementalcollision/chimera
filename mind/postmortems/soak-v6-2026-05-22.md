### The agent's actual code

```python
def detect_ping_pong(
    history: list[ToolCall],
    *,
    min_cycle_length: int = 2,
    max_cycle_length: int = 3,
    abort_at_repeats: int = 2,
) -> LoopVerdict:
    """Detect alternating (ping-pong) cycles in the tail of *history*."""
    if len(history) < min_cycle_length * 2:
        return LoopVerdict.OK

    sigs = [tc.signature() for tc in history]

    for cycle_len in range(min_cycle_length, max_cycle_length + 1):
        needed = cycle_len * (abort_at_repeats + 1)
        if len(sigs) < needed:
            continue

        tail = sigs[-needed:]
        cycle = tail[:cycle_len]

        matches = True
        for i in range(0, len(tail), cycle_len):
            block = tail[i:i + cycle_len]
            if len(block) < cycle_len:
                break
            if block != cycle:
                matches = False
                break

        if matches:
            return LoopVerdict.ABORT

    return LoopVerdict.OK
```

This is real code, not stub. It complements (not duplicates)
`detect_degenerate_loop`: the existing guard catches *identical
consecutive* tool calls (same name + same args), this one catches
*alternating cycles* of length 2–3 (A→B→A→B, A→B→C→A→B→C). The
agent understood the gap from its own investigation doc and shipped
a function that addresses it without overlap.

## What didn't work

### Failure A — runner self-collision (operator-side)

Three failed launches before the clean run because:

1. Initial `nohup &` launch (the first 0306 attempt) survived a
   `pkill` that hit the wrong PID — the script kept running for 20+
   minutes spamming cd-failure errors to the hardcoded log path
2. Second `run_in_background` launch (0308) shared that log file,
   so tail+lsof both showed mixed-up state across two unrelated
   processes
3. Took three rounds of kill + worktree-remove + relaunch + a
   stamped-log-path patch (commit `13e8b8a`) to get to a clean
   single-process run

Lesson for the runner: **stamp the log path, refuse to start if
another instance is alive, kill the entire process group on exit**.
Chips queued.

### Failure B — agent didn't write its own test

Phase 2 INBOX presumably included "write a regression test for
detect_ping_pong in tests/test_loop_guard.py". `artifact_missing=1`
in escalations suggests something fired on this. The fix landed,
the test did not. Possibly the agent considered the fix
self-evidently correct (it does pass the existing test suite); more
likely the budget cap + max_rounds combination drained before the
test step.

This is the natural next failure mode: **agent writes the fix but
not the test that protects the fix from regression**. v4.88 chip:
detect "fix-without-test" as a finish_reason class — when an ACT
turn modifies `chimera/X.py` without a corresponding modification
under `tests/`, that's an artifact-missing-class signal.

### Failure C — version bump confusion

The agent committed "Bump version to 4.86.0" inside the worktree,
not knowing v4.86 had already shipped to main earlier the same
evening. Harmless in this worktree (won't merge), but signals the
agent doesn't have access to the current main version state when
deciding what version to bump to. Worth surfacing via the system
prompt or the INBOX.
