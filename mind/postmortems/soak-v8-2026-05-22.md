## The architectural wins (v8's real value)

### v4.93 graduated trust — validated end-to-end

v7's exact same task sequence drove T5 → T0 LOCKED in 3 escalations.
v8 stayed at T4 after 2× ungrounded_citation + 1× max_rounds. The
arithmetic matches the table exactly:

```
Starting tier: T5
2× ungrounded_citation × (-0.5) = -1.0
1× max_rounds × (0)             = -0.0
                            ─────────
Trust at stop:                  T4   ✓
```

Without v4.93, trust would have been T0 by escalation #3. The
agent would have been in observer mode. We would have repeated v7.
Instead the agent had full ACT access throughout v8 — the failure
mode that surfaced is one layer above trust, not at trust.

### v4.95 degrade-check — integration confirmed

Every cycle in the v8 log shows:

```
chimera trust degrade-check: ok  baseline=T5 current=T5 drop=0 threshold=2
```

(and once after trust dropped to T4: `current=T4 drop=1`). The
helper is invoked, the threshold is honored, no auto-promote fired
(because the drop never exceeded the threshold of 2). The hook is
working exactly as designed.

The interesting test of v4.95 — what happens when drop ≥ threshold
— didn't fire in v8 because v4.93 kept the slope shallow enough. v9
will likely exercise it.

### v4.92 fix_without_test — held in wild conditions

56 calls, 4 task attempts, mixed read+write activity, multiple
chimera/X.py paths in tool args — zero false-positive
fix_without_test firings. The root-cause fix (filter
`write_targets` population by tool name) holds.

## The new failure mode — content-marker blindness

The phase-1 INBOX specifies:

> "Write all of the above to
> `mind/research/ping-pong-wiring-investigation.md`. The file MUST
> end with a section whose heading is EXACTLY:
> `## READY-FOR-REMEDIATION`"

The agent's behavior on attempts 3 and 4:

1. Runs `code_exec` to write *something* to the file
2. Returns `stop` with `completed=True`
3. The file on disk doesn't contain `READY-FOR-REMEDIATION`
4. ACT sees: target file exists → `artifact_missing` doesn't fire
5. ACT marks task complete
6. Runner doesn't transition to phase 2 (no sentinel)
7. Next cycle: agent assigned the same task again
8. Goto 1

This is a closed loop the platform can't break out of. Three of the
existing detectors had something to say but none of them caught it:

- **`artifact_missing`** (v4.81) — checked existence, file exists,
  no fire
- **`scope_evasion`** (v4.82) — checked intended-paths-vs-written,
  intended path == written path, no fire
- **`fix_without_test`** (v4.92) — chimera/X.py wasn't written
  (correct), no fire
- **`ungrounded_citation`** (v4.83) — fired on attempts 1 and 2 but
  not on 3+ (the model's later drafts had no citations at all, only
  unsupported claims, which is a different shape than fabricated
  citations)

The gap: **ACT can verify a path EXISTS but cannot verify it
CONTAINS what the task asked for.**

### The v4.96 surface

Extend `artifact_missing` (or add a new `artifact_incomplete`
finish_reason) that:

1. Parses the task text for content markers: `MUST contain X`,
   `MUST end with X`, `the file must include X`
2. After the write, checks the file content for those markers
3. If a required marker is absent, downgrade `completed=True` to
   `False` with `finish_reason="artifact_incomplete"`
4. Route to v4.84 remediation hint: "Your write to <path> is
   missing the required marker `<marker>`. Use code_exec to append
   the missing section. Don't analyse — just append."

The signal would have fired on attempt 3 of soak v8, the v4.84
hint would have explicitly pointed the model at the missing
sentinel, and (likely) the agent would have appended a section
with the exact heading.

This is a small, well-bounded chip. The regex for marker extraction
is similar to v4.81's path extraction. The check is `marker in
content` — trivial. The risk is false-positives on tasks that
mention "MUST" colloquially but don't actually require a marker;
that's calibrated by requiring the marker to be on its own line
and preceded by `## `, `EXACTLY:`, or quotes.

## What didn't work

The investigation-doc task's hollow-completion pattern is the
single new gap. It's not a regression — the file-existence-only
check has been in `artifact_missing` since v4.81. It just wasn't
tested against a content-required task before. v8 was the first
soak to put a sentinel requirement in the INBOX as a hard
necessity for phase-2 transition. The detector that needed to
catch it didn't exist.

## Chip for v4.96

**v4.96 — `artifact_incomplete` finish_reason for content-marker
violations.**

Extracts required content markers from task text (look for `MUST
contain X`, `MUST end with X`, `EXACTLY: \`X\``, on-own-line `## X`
patterns). After the write, checks file content. If a required
marker is absent, downgrade completed=True → False with
`finish_reason="artifact_incomplete"` and route to v4.84 remediation
hint targeted at appending the missing marker.

Tests in `tests/test_act_completeness.py` (or a new file —
`test_artifact_incomplete.py`):

- v8 fixture: investigation doc without `## READY-FOR-REMEDIATION`
  sentinel
- positive: doc contains the sentinel, no fire
- ambiguity: task mentions "MUST" colloquially but no specific
  marker, no fire
- multiple markers: all must be present
- existing test for `artifact_missing` (file doesn't exist) still
  passes

ADR 0101 documenting the detector. Trust delta in v4.93's table:
treat `artifact_incomplete` as moderate (same as
`fix_without_test`, -1 from current tier).

## Closing observation

Eight soaks deep, the platform now has nine instrumented failure
classes (`max_rounds`, `length`, `artifact_missing`, `scope_evasion`,
`ungrounded_citation`, `fix_without_test`, `silent_failure`, and
two pre-v4.78 classes) and a trust system that calibrates them
proportionally. The work-rate of the soak series has shifted: where
soaks v1-v3 ran for hours and produced single-bit signals, soaks
v7-v8 each ran under an hour and produced an end-to-end validation
PLUS a clean chip surface. The diagnostic loop is now tighter than
the implementation loop.

The completeness frontier (v7's hypothesis) hasn't been fully
tested yet — both v7 and v8 stalled in phase 1 — but the lower
layers needed to even *start* testing it are now solid. Once v4.96
ships, v9 should reach phase 2 cleanly and the question "does the
agent ship both fix AND test?" becomes answerable for the first
time.
