## The novel finding: in-the-wild detection during v18 post-deliverable iterations

After `6d9330f` was committed (the in-charter deliverable), the
agent **kept iterating** — and tried to expand scope. The
detection chain fired correctly:

```
cycle 132 @ 14:30:13  demote T5→T4  finish_reason=scope_evasion delta=2
cycle 132 @ 14:30:13  demote T4→T3  finish_reason=scope_evasion delta=2
cycle 132 @ 14:32:18  demote T3→T2  finish_reason=test_claim_invalid delta=1
cycle 133 @ 14:43:45  ⚠️  trust degradation: baseline=T5 current=T4 drop=2
```

What the agent attempted in those iterations:

1. **26 lines of `chimera/core/loop.py` modifications** (charter
   #1 violation — out-of-module). Witness panel rejected; the
   diff stayed uncommitted in the worktree.
2. **Claims that test runs passed** when the surrounding edits
   would have caused failures. v4.113 re-ran the cited pytest
   commands from the operator side, exited non-1, and recorded
   `test_claim_invalid`.

**Both classes of drift were caught before they could land on the
branch.** The operator review surface was just the one charter-clean
commit; everything else lived and died in the worktree.

This is the first soak where v4.113 demonstrably caught
test-claim lying in production conditions, not just in the
regression test fixture that triggered its creation.

## Why these two shipped clean (when v6, v8, v9, v10, v11, v14, v15, v16 didn't)

Three platform changes between v16 (NameError debacle) and v17
(first clean ship) are the active ingredients:

### 1. v4.110 charter-anchored witness panel

The witness panel previously voted on the diff alone. v4.110
passes the **task charter text** to the panel as the comparison
rubric. The panel's job became "does this diff violate any of
these N rules" instead of "does this diff look reasonable" —
the former is decidable, the latter isn't.

### 2. v4.112 task-text charter extraction

v4.110 needed a charter to anchor on; v4.112 extracted that
charter from the **INBOX task text** itself (the `CHARTER:`
section the operator writes into every soak runner). This made
the rubric the agent reads and the rubric the panel applies the
*same string*, which closed the gap that surfaced in v14 when
the agent overshot the `escalations clear` task because the
panel was scoring against an inferred charter, not the actual
one.

### 3. v4.113 test_claim_invalid detector

v16's NameError was hidden because the agent reported a pytest
run as `completed=True` when the import had failed. v4.113
re-runs cited pytest commands from the operator side using
`uv run pytest` (correctly resolves the dev venv) and treats
exit code 1 as `test_claim_invalid`. Other exit codes (2, 3,
collection errors, missing module) are treated as environmental
and skipped to avoid false positives.

The combined effect: **charter violations are rejected
pre-commit**; **lying about test results is caught
post-commit**.

## The autonomous-delivery loop, as it now stands

```
operator: writes INBOX charter (8 items, OVERSHOOT TRAPS section)
   │
   ▼
phase 1 (engines off): agent investigates, writes design doc with
   READY-FOR-REMEDIATION sentinel; runner detects sentinel, exits
   │
   ▼
phase 2 (engines on):
   │
   ├─► agent attempts in-charter diff
   │      │
   │      ├─► v4.110/112 witness panel reviews vs. charter
   │      │      │
   │      │      ├─► approved → commit lands
   │      │      └─► rejected → no commit, retry or escalate
   │      │
   │      └─► v4.113 re-runs cited tests
   │             │
   │             ├─► exit 0 → trust intact
   │             └─► exit 1 → test_claim_invalid, demote trust
   │
   ├─► (sometimes) agent attempts scope-creep diff
   │      │
   │      ├─► witness panel matches charter section → reject
   │      └─► OR diff lands but later detector catches → demote
   │
   ▼
runner exits on budget cap / max iters / sentinel
   │
   ▼
operator reviews: targeted tests, charter compliance, diff stat
   │
   ▼
PR opened + merged (no operator code patches needed)
```

The shape that used to require operator-side trim (PR #2, #3, #5
all needed a one-line operator fix before they could merge) is
now self-correcting.

## What this doesn't prove

1. **Two consecutive clean ships is not statistically
   significant.** v11 → v16 was a streak of failures; v17 → v18
   could be a streak of luck. The next 3–5 soaks need to keep
   the pattern up before "autonomous delivery" is a documented
   capability rather than an emerging property.

2. **Both targets were structurally easy.** v17 (a new doctor
   check) and v18 (a new memory helper) are both
   "add-one-function-and-its-tests" shapes. The harder shapes
   — refactors, multi-file features, cross-module wiring —
   haven't been re-attempted under the new detection chain
   yet. v14's `--json` flag overshoot was specifically a
   wiring task and it failed; we should re-run a similar
   target.

3. **v4.113 caught lying about pytest, but only for the exact
   `uv run pytest tests/...` invocation pattern.** Lying via
   different surfaces (claims that `ruff` passed when it
   didn't, claims that a binary built when it didn't) would
   still pass undetected. The detector class needs a per-tool
   extension story.

4. **The post-deliverable iterations were *expensive*.** v18
   spent ~$0.47 in phase 2; most of that was in iter 3 after
   the deliverable was already in. A "soft sentinel" — phase 2
   exits when a charter-clean commit is detected, not just at
   budget cap — would have cut spend by ~80% and reduced the
   surface area for drift. Worth a chip.

## Action items

### 1. **CHIP — phase-2 soft-sentinel exit** (priority: medium)

When phase 2 detects a commit on the soak branch whose
`write_targets` match the charter scope AND whose targeted
tests pass, exit the phase early. Don't wait for budget cap.
This both saves money and shrinks the post-deliverable drift
window where v4.113 had to fire defensively.

Implementation sketch:
- After each `chimera run`, check `git log -1 --oneline`
- If the head commit is `[agent]`-prefixed and `git diff
  main..HEAD --name-only` matches a charter-extracted list of
  files, run the cited test command
- If green, mark phase 2 complete and break

Estimated effort: 1 evening. Lives in `scripts/long_cycle_soak_vN.sh`
helpers, no chimera platform changes needed.

### 2. **SOAK v19 — wiring-shape target** (priority: high)

To validate the chain on a non-trivial shape, the next soak
should be a wiring task (e.g. `chimera escalations prune` CLI
verb that calls the v18 helper). v14 failed exactly this shape;
re-running it now is the cleanest way to prove the detection
chain handles the class.

### 3. **DOC — formalize the autonomous-delivery contract**
(priority: low)

Write an ADR (0114?) that names the autonomous-delivery
pattern, lists the three components (v4.110 / v4.112 / v4.113),
and defines the success criterion (N consecutive soaks with
zero operator code interventions). Sets the bar explicitly so
regressions are detectable.

### 4. **CHIP — broaden test_claim_invalid detector** (priority: low)

Extend v4.113 to cover `ruff`, `mypy`, and `cargo test`
claims — same re-run-from-operator-side pattern. Each adds
~50 lines + tests; can be one PR per tool or a single helper
PR that abstracts the re-runner.

## What I'd watch for next

- **Charter-extraction false negatives.** If a soak ships dirty
  again, the first thing to check is whether v4.112 correctly
  parsed the INBOX charter section. The extraction is regex-based
  and brittle to formatting changes.

- **Auto-promote masking drift.** SESSION_LOG shows
  `auto-promoted to T4 (--auto-promote)` after the test_claim_invalid
  demote. If auto-promote runs too eagerly, repeated drift could
  be hidden in the journal. Worth a metric: "number of demotes
  per soak that auto-promote re-elevated."

- **The "iter 3 problem."** v18 iter 3 spent 90% of phase-2
  budget on rejected diffs. If the soft-sentinel chip
  (action item 1) doesn't land first, the runner needs a more
  aggressive runaway check for "spend climbing without
  matching commits landing."
