## What didn't work

### Failure A — the recovery loop

After v4.82 fired, the agent retried the same task twice:

```
ACT: 'Write a regression test in tests/test_loop_guard.py...'
     → scope_evasion (rounds=6, tools=11, completed=False)
ACT: 'Write a regression test in tests/test_loop_guard.py...'
     → length        (rounds=20, tools=26, completed=False)
ACT: 'Write a regression test in tests/test_loop_guard.py...'
     → length        (rounds=12, tools=18, completed=False)
```

Both retries hit `length` (max output tokens). The model wrote
extensive analysis instead of just calling `code_exec` to write
the file. It received the scope_evasion signal but didn't change
strategy in response.

This is the structural gap soak v5 surfaced. **v4.82 tells the
model what was wrong; nothing tells the model what to do
differently.** When scope_evasion appears in escalation memory,
ACT should inject a hint into the next prompt: "Your previous
attempt didn't write to <path>. Use code_exec to create or modify
this file. Don't analyse — just edit."

That's the v4.84 chip.

### Failure B — the missed task

The "Implement the fix per the sketch" task also named two paths:

```
"Most likely files:
  `chimera/tools/loop_guard.py` (if false-positive...)
  OR `chimera/core/act.py` (if correct...)"
```

The agent reported `completed=True` in 15 rounds with zero
chimera/ writes. **v4.82 did NOT fire on this task.** Either the
regex didn't catch the path (because of the multi-line "OR"
layout), or the check is gated to specific task shapes.

If v4.82's regex requires a single backtick-quoted path on the
same line as the verb, the "Implement the fix... most likely
files: \`chimera/x\` OR \`chimera/y\`" layout slips through. That's
exactly the v4.81 multi-line bug class, one level up. v4.85 should
port v4.81's continuation-line fold logic into v4.82's
path-extraction.

## The detection/recovery split

After 5 soaks, the platform layer is solid AND the detection layer
is solid. Five orthogonal failure modes have been instrumented:

```
v4.79 / v4.81 → artifact_missing       (silent phantom completion)
v4.82         → scope_evasion          (wrote to wrong scope)
v4.83         → ungrounded_citation    (fabricated symbol names)
v4.46 (older) → escalation memory      (records all of the above)
```

What's NOT yet instrumented is **what the agent does after detection
fires.** Currently: re-prompts with the same task text, hopes the
model figures it out, hits length limit when it doesn't, gives up.
The escalation memory has the diagnosis; the next-cycle prompt
doesn't surface that diagnosis to the model.

This is the natural next layer. The chip prompt for v4.84 outlines
the surface: when `task_escalations` for a given signature has a
recent `scope_evasion` / `artifact_missing` / `ungrounded_citation`
entry, ACT's next attempt at a related task should include a
remediation hint specific to that failure mode.
